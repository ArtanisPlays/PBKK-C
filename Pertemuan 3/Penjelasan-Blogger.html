Pertemuan 3 PBKK C: Membuat Scientific Calculator dengan Windows Forms

Mata kuliah: Pemrograman Berbasis Kerangka Kerja C (2026)
Pertemuan: 3 — Scientific Calculator Apps

Pada pertemuan ini saya membangun aplikasi kalkulator saintifik desktop berbasis Windows Forms menggunakan C# dan .NET. Aplikasi ini dirancang untuk dapat mengevaluasi ekspresi matematika berantai yang kompleks—termasuk operasi aritmatika hierarkis, tanda kurung bersarang, fungsi trigonometri (derajat/radian), logaritma, eksponensial, pemangkatan, akar, faktorial, serta pengelolaan memori kalkulator.

1. Arsitektur dan Struktur Kode

Aplikasi ini memisahkan secara tegas antara lapisan antarmuka pengguna (UI) dan lapisan logika komputasi matematika:

  • Program.cs: Titik masuk utama (entry point) yang menginisialisasi runtime Windows Forms melalui ApplicationConfiguration.Initialize() dan menjalankan form kalkulator.
  • CalculatorForm.cs: Lapisan presentasi yang membangun seluruh tata letak antarmuka secara terprogram, menangani interaksi klik tombol keypad, pintasan keyboard fisik, dan mengelola state antarmuka.
  • CalculatorEngine.cs: Mesin logika murni yang bertugas mem-parsing dan mengevaluasi string ekspresi matematika menggunakan algoritma Recursive Descent Parser.

2. Penjelasan Mendalam Mesin Evaluasi (CalculatorEngine.cs)

CalculatorEngine tidak mengeksekusi ekspresi menggunakan compiler eksternal yang lambat atau tidak aman, melainkan mengimplementasikan parser matematika mandiri dengan aturan tata bahasa (grammar) berlapis untuk menjamin prioritas operator (operator precedence):

A. Normalisasi Input (Method Evaluate)

string normalized = expression.Replace("×", "*").Replace("÷", "/").Replace("−", "-")
    .Replace("π", "pi").Replace("√", "sqrt");

Sebelum diproses oleh parser, simbol visual tombol antarmuka (seperti ×, ÷, −, π, dan √) dinormalisasi menjadi representasi token standar yang dimengerti parser (*, /, -, pi, dan sqrt).

B. Hierarki Grammar dan Precedence Parsing

Parser membaca string karakter per karakter dari kiri ke kanan dengan tingkatan prioritas dari yang terendah ke yang tertinggi:

  1. Penjumlahan dan Pengurangan (Expression() & Additive()): Mengevaluasi operator + dan - setelah memproses perkalian/pembagian di kedua sisinya.
  2. Perkalian dan Pembagian (Term()): Mengevaluasi operator * dan /. Di sini dilakukan deteksi pembagian dengan nol (Math.Abs(d) < 1e-15) yang langsung melemparkan DivideByZeroException.
  3. Pemangkatan (Power()): Mengevaluasi operator ^ secara right-associative (rekursif ke kanan) sehingga ekspresi 2^3^2 dievaluasi sebagai 2^(3^2) = 512.
  4. Operator Unary (Unary()): Menangani tanda positif atau negatif tunggal di depan angka atau tanda kurung, seperti -5 atau -(3 + 2).
  5. Operator Postfix (Postfix()): Menangani operator faktorial !. Method Factorial() memvalidasi agar input hanya menerima bilangan bulat positif dalam rentang 0 sampai 170 (mencegah overflow nilai double floating-point).
  6. Unit Terkecil (Primary()): Menangani token dasar:
    • Tanda kurung ( ... ) yang mengevaluasi subekspresi di dalamnya terlebih dahulu.
    • Bilangan desimal (Number()) yang diparsing dengan CultureInfo.InvariantCulture.
    • Konstanta matematika pi (π), e (Euler), dan ans (hasil perhitungan terakhir).
    • Fungsi matematika (Function()).

C. Dukungan Fungsi Saintifik dan Konversi Sudut

double rad = degrees ? x * Math.PI / 180.0 : x;

Ketika mode derajat (DEG) aktif, input untuk fungsi trigonometri (sin, cos, tan) secara otomatis dikonversikan ke satuan radian sebelum diproses oleh Math.Sin dkk. Sebaliknya, fungsi inverse trigonometri (asin, acos, atan) mengembalikan sudut yang dikonversikan kembali ke derajat melalui method FromRad().

Selain itu, engine juga memeriksa validitas domain input (misalnya sqrt untuk bilangan non-negatif, ln dan log untuk bilangan positif > 0, serta asin/acos dalam rentang -1 hingga 1).

3. Penjelasan Mendalam Antarmuka dan Event Handling (CalculatorForm.cs)

A. Tata Letak Terprogram (Programmatic UI Layout)

Antarmuka dibangun sepenuhnya lewat kode C# menggunakan struktur kontrol bersarang:

  • Header Panel: Menampilkan judul aplikasi dan tombol toggle mode sudut DEG / RAD.
  • Display Panel: Terdiri dari label mode, TextBox ekspresi berukuran font besar, label hasil kalkulasi tebal (bold), dan label nilai Ans sebelumnya.
  • Keypad Grid (TableLayoutPanel): Matriks tombol 6 kolom × 9 baris yang disusun responsif. Tombol angka diberi warna putih bersih, tombol fungsi berlatar pastel ungu lembut, dan tombol sama dengan (=) diperlebar melintasi 3 kolom dengan warna aksen tegas.

B. Manajemen Input Tombol (Method Press dan Append)

Ketika tombol ditekan, method Press memetakan teks tombol menjadi token fungsi yang sesuai:

  • Tombol fungsi seperti sin, cos, ln, dan √x secara otomatis menambahkan kurung buka (misal menjadi sin( atau sqrt().
  • Tombol ± membungkus ekspresi aktif dengan tanda negatif -(...).
  • Tombol % membagi ekspresi dengan 100 (...)/100.
  • Method Append memastikan bahwa jika pengguna mengetikkan angka baru tepat setelah perhitungan selesai, tampilan ekspresi otomatis dibersihkan untuk memulai perhitungan baru tanpa harus menekan AC manual.

C. Fitur Memori Kalkulator

Kalkulator menyediakan fungsionalitas memori lengkap:

  • MS (Memory Store): Menyimpan nilai hasil atau ekspresi saat ini ke variabel memory.
  • M+ & M-: Menambahkan atau mengurangkan nilai saat ini ke dalam memori secara akumulatif.
  • MR (Memory Recall): Memasukkan nilai yang tersimpan di memori ke dalam ekspresi aktif.
  • MC (Memory Clear): Mengosongkan nilai memori menjadi 0.

D. Penanganan Keyboard Fisik (Method HandleKey)

Dengan mengaktifkan KeyPreview = true pada Form, kalkulator dapat dioperasikan langsung menggunakan keyboard komputer:

  • Angka 0-9 (baik baris atas maupun Numpad) langsung mengetikkan angka.
  • Tombol Enter menjalankan kalkulasi (Calculate()).
  • Tombol Backspace menghapus satu karakter terakhir (⌫).
  • Tombol Escape mereset seluruh layar (AC).
  • Tombol titik/desimal (.) memasukkan tanda koma desimal.

4. Error Handling

Kalkulator membungkus proses evaluasi dalam blok try-catch. Apabila terjadi kesalahan sintaks (misal kurung tidak ditutup) atau kesalahan matematika (misal pembagian nol atau logaritma bilangan negatif), aplikasi tidak akan berhenti mendadak (crash). Sebagai gantinya, pesan galat yang deskriptif dari parser langsung ditampilkan pada label hasil.
